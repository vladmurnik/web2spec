# Источники данных для web2spec

Документ отвечает на один вопрос: откуда взять пары «HTML → JSON» для дообучения
Qwen2.5-0.5B, чтобы не нарушить лицензии и не собирать мусор. Все ссылки проверены
HTTP-запросом 2026-11-03, если в таблице не указано иное. Лицензии указаны по
карточкам источников; перед скачиванием их нужно перепроверить — они меняются.

## 1. Публичные датасеты HTML → структура

| Источник | Что внутри | Лицензия | Как адаптировать |
|---|---|---|---|
| [HuggingFaceM4/WebSight](https://huggingface.co/datasets/HuggingFaceM4/WebSight) | ~830 тыс. синтетических пар «скриншот/HTML» на английском | указана на карточке (проверить) | Взять HTML, прогнать через `compress_html`, целевой JSON собрать из DOM по схеме `extract` |
| [Design2Code](https://github.com/NoviScl/Design2Code) | 484 реальные страницы, screenshot → HTML | MIT (репозиторий) | Только как эталон структуры; пары «HTML → поля» строить вручную |
| [Web2Code](https://github.com/MBZUAI-LLM/Web2Code) | Веб-страницы и код, ~1 млн примеров | проверить карточку | HTML уже есть; цель — JSON-спека (`task: spec`), а не свободный код |
| [Web Data Commons](https://webdatacommons.org/) | schema.org microdata/JSON-LD, извлечённые из Common Crawl | зависит от краула и сайтов | Лучший источник silver-пар: HTML страницы + извлечённый JSON-LD как `target` |
| SWDE (Structured Web Data Extraction) | ~80 тыс. страниц, 8 вертикалей (книги, авто, кино) | academic use | Прямое соответствие `extract`; проверить условия распространения |
| [WebSRC](https://github.com/x-lance/WebSRC) | 6,4 тыс. страниц, ~400 тыс. QA-пар | academic use | Задача `qa`: вопрос + HTML → короткий JSON-ответ |
| [Mind2Web](https://github.com/OSU-NLP-Group/Mind2Web) | 2 тыс. задач, 137 сайтов, траектории агента | academic use | Не для v1; пригодится для политики поиска по сайту (Stage F) |
| [Common Crawl](https://commoncrawl.org/) | Сырые WARC-архивы | условия краула + ToS сайтов | Только как сырьё; хранить URL и соблюдать robots.txt. HEAD-проверка не прошла, сайт считается непроверенным |

Практический вывод: чистых пар «HTML → произвольный JSON» в открытом доступе мало.
WebSight и Web Data Commons дают масштаб, но требуют переразметки под нашу схему.
100–300 размеченных вручную страниц всё равно нужны как золотой стандарт.

## 2. Репозитории, из которых делают пары

| Репозиторий | Роль | Что взять |
|---|---|---|
| [scrapy/scrapy](https://github.com/scrapy/scrapy) | Сбор страниц | Пауки, очередь, throttling, robots.txt |
| [microsoft/playwright-python](https://github.com/microsoft/playwright-python) | JS-страницы | Рендер динамики, ожидание селекторов |
| [apify/crawlee](https://github.com/apify/crawlee) | Оркестрация | Retry, прокси, дедупликация URL |
| `extruct` | Извлечение schema.org | JSON-LD/microdata → silver `target` |
| `trafilatura` | Очистка основного текста | Сравнение с `compress_html`, отсев навигации |
| `readability-lxml` | Выделение статьи | То же для новостных страниц |

Схема получения silver-пары: страница → `extruct` → JSON-LD → маппинг в нашу схему →
`validate_sample`. Если JSON-LD нет, страница идёт в ручную разметку, а не в мусор.

## 3. Русскоязычные источники

| Источник | Тип | Ограничение | Как использовать |
|---|---|---|---|
| Ozon, Wildberries, Avito | E-commerce, классифайды | ToS запрещают автоматический сбор; есть капчи | Только партнёрские фиды или собственные/разрешённые страницы |
| Яндекс Маркет (фид) | Товарные фиды | По договору партнёрской программы | JSON/XML фид → синтетические HTML-карточки → пары |
| [data.mos.ru](https://data.mos.ru/) | Открытые данные Москвы | Открытая лицензия портала | Сгенерировать страницы по шаблону и получить чистые пары |
| Русская Википедия | Энциклопедия | CC BY-SA | Инфобоксы → JSON, текст статьи → `qa` |
| Habr | Статьи | Пользовательский контент, ToS | Только с разрешения авторов/редакции |
| Демо-магазины CMS (Bitrix, OpenCart) | Витрины | Лицензия демо-контента | Быстрый seed-набор без юридических рисков |

Минимум три источника для русского языка выполняются: Маркет-фид, data.mos.ru,
Википедия. Этого достаточно для seed-набора; дальше — синтетика и партнёрские фиды.

## 4. Seed-набор: 100 страниц за один день

| Время | Шаг | Результат |
|---|---|---|
| 09:00 | Отбор: 5 доменов × 20 URL, только легальные/партнёрские | `data/raw/seed_urls.csv` |
| 10:00 | Сбор: Playwright, проверка robots.txt, пауза 1–2 с | 100 HTML в `data/raw/seed/` |
| 11:00 | Правила разметки: только видимый текст, цена = число + валюта, отсутствие = `null`, ничего не придумывать | `docs/ANNOTATION.md` |
| 13:00 | Два аннотатора размечают по 50 страниц независимо | 100 JSON |
| 15:00 | Сверка расхождений, третий проход по спорным | согласованный набор |
| 16:00 | `scripts/01_validate.py`, карантин, проверка длины | отчёт валидации |
| 17:00 | Заморозка v1: хэши файлов, `group_id = host` | `data/processed/seed-v1/` |

Правила приёмки seed: 0 ошибок схемы, ≤5% расхождений между аннотаторами,
ни одной страницы с персональными данными, у каждой пары заполнен `source_url`.
Если расхождение выше 5%, правила разметки переписываются, а не подгоняются примеры.

## 5. Синтетическое расширение

1. Teacher-модель (Qwen2.5-Coder-32B или сильнее) получает сжатый HTML и JSON Schema.
2. Ответ проходит `extract_json` → `validate_sample` → дедупликацию.
3. 5% принятых примеров проверяет человек; если доля ошибок >10%, синтетика не идёт в train.
4. 10% примеров прогоняются через вторую teacher-модель; расхождение — сигнал брака.

Ожидаемый выход: 60–85% ответов проходят схему (оценка, не факт). Стоимость
зависит от провайдера; при локальном 7B-teacher на 4 GB счёт идёт на дни, поэтому
для генерации нужен внешний API или машина с большей VRAM.

## 6. Лицензии и этика

- robots.txt и ToS проверяются до сбора, а не после.
- Не обходить капчи, paywall и авторизацию.
- Вырезать PII (имена, телефоны, адреса) из HTML и целей; хранить только URL-хост.
- Текст страниц не перепубликовывать: датасет распространяется как производные
  структуры, а не как копия сайта.
- Для русского рынка учитывать 152-ФЗ; для ЕС — GDPR.
- Указывать источник и дату сбора в `meta.source_url` и `meta.pipeline_version`.

## 7. Чего не использовать

- «Датасеты» с утёкшими паролями, почтами, паспортами.
- Скрейпы без лицензии и без указания происхождения.
- Страницы с капчами и антибот-обходами.
- Синтетику без валидации схемой и без выборочного аудита.
- Данные, собранные с сайтов, чьи ToS прямо запрещают обучение моделей.
